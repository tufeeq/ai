# التشغيل داخل TAGit NEXT

هذه النسخة مركّبة في مستودع `tufeeq/ai` وتظهر في [تبويب TAGit Lab](https://tufeeq.github.io/ai/tagit-next/#lab).

- الكود: `tagit-lab/` على `main`؛ الواجهة: `tagit-next/lab/`.
- التشغيل: مهمة **TAGit Lab** في GitHub Actions. عند تحديث الكود تعمل الاختبارات وفحص اتصال Alpaca الحقيقي؛ وبعد الإغلاق تعمل المتابعة اليومية الساعة 21:40 UTC من الاثنين إلى الجمعة، مع استخدام تقويم التداول.
- `check`: فحص الشموع التاريخية والتقويم. `forward`: تقييم آخر جلسة منتظمة مكتملة، أو تاريخ محدد. `research`: تنفيذ بحث التطوير وwalk-forward وحساسية التكلفة. لا تفتح المهمة العينة المختومة تلقائيًا.
- المفاتيح الحالية مدعومة بالأسماء `ALPACA_API_KEY_ID` و`ALPACA_API_SECRET_KEY` وأسماء Alpaca البديلة. إن لم تتوفر أسرار GitHub، يستخدم المحرك `TAGIT_LAB_PROXY_URL` للوصول إلى مسار القراءة فقط على خادم Render الحالي. المفاتيح تبقى في الخادم.
- مسار الاتصال: `/api/lab/connection`. مسار البحث: `/api/lab/provider`، بطلبات GET فقط إلى مسارات Alpaca محددة. مصدر البحث SIP تاريخي؛ لا يُستبدل تلقائيًا بـ IEX عند فشل الصلاحية.
- النتائج العامة: `tagit-next/lab/results/summary.json`؛ السجل الأصلي ونتائج البحث: `tagit-lab/results/` وملف artifact لكل تشغيل. اكتمال مهمة المختبر يعيد نشر GitHub Pages تلقائيًا.
- المتابعة اليومية تقييم بأثر رجعي لإشارات الجلسة المكتملة، وليست سجل أوامر تداول منفذة. الجلسات بلا إشارات تُسجّل مرة واحدة، ويُرفض تغيير الإعدادات فوق سجل قائم أو إضافة جلسات أقدم بعد الأحدث.
- تبقى أرقام الأداء فارغة حتى تُنتج البيانات الحقيقية نتائج. المثال المصطنع المرفق لا يُعرض كأداء للسوق.

اختبار محلي:
```bash
cd tagit-lab
pip install -r requirements-dev.txt
python -m pytest -q
python -m tagit_lab.publish --probe
```

# TAGit Lab: محرك التحقق والإشارة لأداة TAGit NEXT

هذا المحرك يجيب عن سؤال واحد قبل أي تطوير آخر: **هل تحقق قاعدة الإشارة عائداً موجباً بعد التكلفة، على بيانات لم تُستخدم في تصميمها؟**

يعمل بالكامل على مصادر مجانية، ويمكن تشغيله على جهازك أو على خوادم GitHub Actions المجانية.

---

## ما الذي تغيّر مقارنة بالمنهجية الحالية

| الجانب | الوضع الحالي | في TAGit Lab |
|---|---|---|
| مصدر البيانات | IEX: بورصة واحدة وجزء صغير من الحجم | **SIP موحّد** يغطي كل البورصات، من Alpaca مجاناً (لما هو أقدم من 15 دقيقة) |
| حجم العينة | 10 جلسات و84 إشارة قابلة للتقييم | 18 شهراً للتطوير و6 أشهر مختومة، أي آلاف الإشارات المتوقعة |
| القيمة السوقية | الحالية | **في تاريخها الفعلي**: الأسهم القائمة حسب تاريخ إيداعها في SEC EDGAR |
| الأسهم المشطوبة | غير مشمولة غالباً | مشمولة (قائمة Alpaca للأصول النشطة وغير النشطة) |
| تقييم الصفقة | نافذة تالية | **Triple Barrier**: وقف أو هدف أو حد زمني، أيها يُلمس أولاً، مع قواعد محافِظة |
| التكلفة | افتراضية ثابتة | نصف الفرق مقدّر لكل سهم (Abdi–Ranaldo) + انزلاق، مع اختبار حساسية ×2 و×3 |
| فواصل الثقة | غير موجودة | إعادة معاينة **حسب اليوم** لا حسب الصفقة (لأن إشارات اليوم الواحد مترابطة) |
| تعدد التجارب | غير محتسب | Benjamini–Hochberg ونسبة شارب المخفّضة (Deflated Sharpe) |
| خارج العينة | غير موجود | Walk-forward شهري + عينة مختومة تُفتح مرة واحدة + متابعة حية يومية |
| الطرح والتخفيف | غير محتسب | إيداعات S-1 وS-3 و424B و8-K (بند 3.02) بوقت قبولها الدقيق |
| السجل | في المتصفح ويضيع | ملف دائم في المستودع يُحدَّث آلياً بعد كل جلسة |

## المتغيّرات المختبرة

كل متغيّر تعديل واحد على القاعدة الحالية، إضافة إلى مزيج واحد. **العدد مقصود أن يبقى صغيراً**، لأن كل متغيّر إضافي يرفع احتمال "اكتشاف" ربحية بالصدفة، وهذا العدد يدخل في التصحيح الإحصائي.

| المتغيّر | الفكرة |
|---|---|
| `baseline` | القاعدة المنشورة حالياً كما هي |
| `no_extended` | استبعاد الحركة الممتدة (فوق 25٪ لليوم أو 8٪ في 3 دقائق) |
| `rvol_tod` | الحجم مقارنةً بالمعتاد **لهذا التوقيت من اليوم** (≥ 3 أضعاف)، لا بمتوسط بسيط |
| `price_ge_1` | استبعاد الأسهم دون دولار |
| `spread_cap` | استبعاد الأسهم التي يتجاوز نصف فرقها المقدّر 75 نقطة أساس |
| `no_dilution` | استبعاد السهم خلال 30 يوماً من إيداع طرح أو تخفيف |
| `skip_open_15` | تجاهل أول 15 دقيقة من الجلسة |
| `target_1r` / `hold_15` / `window_low_stop` | بدائل للخروج |
| `wide_stop` | وقف لا يقل عن 3٪. في الأسهم الصغيرة قد تتجاوز تكلفة الدخول والخروج 1–2٪، فيصبح الوقف الضيق خاسراً بنيوياً |
| `quality_combo` | مزيج فلاتر الجودة أعلاه |

## التشغيل

### 1. المفاتيح المجانية
- **Alpaca:** أنشئ حساب Paper مجانياً من alpaca.markets، ثم خذ `ALPACA_KEY_ID` و`ALPACA_SECRET_KEY`.
- **SEC:** لا يحتاج حساباً، فقط تعريف بالجهة في `SEC_USER_AGENT`، مثل `"TAGit Research you@example.com"`.

### 2. على جهازك
```bash
pip install -r requirements-dev.txt
pytest -q                                   # 21 اختباراً، منها اختبار منع التسرّب من المستقبل
export ALPACA_KEY_ID=... ALPACA_SECRET_KEY=... SEC_USER_AGENT="..."

python -m tagit_lab fetch --start 2024-07-01 --end 2025-12-31   # قرابة ساعة في المرة الأولى
python -m tagit_lab backtest                 # كل المتغيّرات على فترة التطوير
python -m tagit_lab walkforward              # الاختيار الشهري خارج العينة
python -m tagit_lab stress --variant baseline
python -m tagit_lab report                   # results/report.html
```

### 3. على GitHub Actions (بلا جهاز وبلا خادم)
1. انسخ المجلد إلى مستودع، وأضف الأسرار الثلاثة من: Settings ← Secrets ← Actions.
2. شغّل **TAGit research** يدوياً من تبويب Actions، وستُحفظ النتائج والتقرير في المستودع.
3. **TAGit forward tracking** يعمل تلقائياً بعد كل جلسة، فيقيّم إشارات اليوم الحقيقية ويضيفها إلى `results/forward/`.

### 4. العينة المختومة (مرة واحدة فقط)
بعد مراجعة نتائج walk-forward واختيار متغيّر واحد:
```bash
python -m tagit_lab holdout --variant <الاسم>
```
يُختم الإعداد ببصمة في `results/holdout.lock.json`، وأي محاولة لإعادة الفتح بإعداد مختلف تُرفض وتُسجَّل. أوامر التطوير نفسها ترفض أي نطاق يلمس هذه الفترة.

## متى يحق القول إن المنهجية "ناجحة"؟

كل الشروط التالية معاً:
1. **Walk-forward:** 500 صفقة على الأقل خارج العينة، وفاصل الثقة 95٪ لمتوسط العائد بعد التكلفة **لا يشمل الصفر**.
2. **الاستقرار:** أغلب الأشهر النشطة موجبة، وأكبر 5 أسهم لا تصنع معظم الربح.
3. **التكلفة:** تبقى النتيجة موجبة عند مضاعفة التكلفة.
4. **العينة المختومة:** تؤكد النتيجة بنفس الإعداد دون تعديل.
5. **المتابعة الحية:** لا تناقض ما سبق بعد عدد كافٍ من الصفقات.

إن فشل أي منها، فالنتيجة الصحيحة هي إعلان أن القاعدة غير مثبتة وعرضها كأداة **رصد** لا كأداة **قرار**. التقرير يطبع هذا الحكم تلقائياً ولا يجمّله.

## الربط بالواجهة الحالية

`js/tagit-signal.js` نسخة مطابقة لمنطق Python، ومطابقتها مختبرة آلياً سطراً بسطر (`tests/test_js_parity.py`)، فما يظهر للمستخدم هو بالضبط ما اختُبر:

```html
<script src="tagit-signal.js"></script>
<script>
  const S = await (await fetch("results/forward/summary.json")).json();
  const f = TagitSignal.computeFeatures(grid, ctx, TagitSignal.defaultCurve());
  const r = TagitSignal.evaluate(f, i, S.rules.signal, ctx, SESSION);
  // r.pass: هل تحققت الإشارة؟  r.checks: كل شرط على حدة، لعرض "سبب الظهور"
  const plan = TagitSignal.planLevels(f, i, S.rules.exit, lastPrice);
  // S.summary و S.verdict: الأداء الحي الفعلي لعرضه في قسم "المنهجية وحدود المعلومات"
</script>
```

## حدود معروفة (مذكورة في التقرير أيضاً)
- البورصة المدرجة مأخوذة من قائمة Alpaca **الحالية**، لا التاريخية.
- الرموز بلا CIK في EDGAR لا تُعرف قيمتها السوقية فتُستبعد، وعددها يُسجَّل.
- رقم الأسهم القائمة قد ينحرف إذا حدث تقسيم بين تاريخ الإيداع ويوم الإشارة.
- أيام الإغلاق المبكر مستبعدة.
- نصف الفرق **مقدّر** من الشموع اليومية. الدالة `Alpaca.first_quote` تتيح قياسه فعلياً عند كل إشارة، وهي خطوة تحسين تالية.
- **للتحقق عند أول تشغيل حقيقي:** توقيت `acceptanceDateTime` في EDGAR، إذ يُعامل هنا بتوقيت نيويورك رغم لاحقة `Z`. قارن إيداعاً واحداً معروفاً بموقع SEC قبل الاعتماد على فلتر الطرح.
